# Dataverse Schema Definition

Naming convention used below:
- Publisher prefix: `bcr_`
- Display names are user-facing.
- All tables have standard Dataverse columns (`createdon`, `createdby`, `modifiedon`, `modifiedby`, `ownerid`).

## 1) Table: BudgetLine
- **Logical name**: `bcr_budgetline`
- **Display name**: Budget Line
- **Primary name column**: `bcr_budgetlinekey` (Budget Line Key)

### Columns
| Logical Name | Display Name | Type | Required | Default / Choices |
|---|---|---:|---:|---|
| bcr_budgetlinekey | Budget Line Key | Text (max 100) | Yes | Alternate key, unique, stable from Excel |
| bcr_fiscalyear | Fiscal Year | Whole Number | Yes | None |
| bcr_costcenter | Cost Center | Text | Yes | None |
| bcr_budgetcode | Budget Code | Text | Yes | None |
| bcr_category | Category | Choice | Yes | Hardware/Software/Services/Other |
| bcr_pillar | Pillar | Choice | Yes | Security/Infrastructure/Workplace/Data/BusinessApps/Other |
| bcr_owner | Owner | Lookup (System User) | Yes | None |
| bcr_estimatedvalue | Estimated Value | Currency | Yes | 0 |
| transactioncurrencyid | Currency | Lookup (Currency) | Yes | Tenant base currency |
| bcr_renewaldate | Renewal Date | Date Only | No | None |
| bcr_derivedstage | Derived Stage | Choice | Yes | Loaded, ReadinessRequested, ReadinessInProgress, AwaitingPillarValidation, ReadinessReworkRequired, CommercialDiscussionReady, CommercialDiscussionInProgress, CommercialDiscussionComplete, PartiallyOrdered, Ordered, Closed, Parked |
| bcr_last_event_type | Last Event Type | Choice | No | Same enum as EventLog Event Type |
| bcr_last_event_at | Last Event At | DateTime | No | None |
| bcr_manualstageoverride | Manual Stage Override | Choice | No | Same enum as Derived Stage |
| bcr_manualoverridejustification | Manual Override Justification | Multiline Text | Conditionally required | Required when override set |
| bcr_manualoverrideat | Manual Override At | DateTime | No | None |
| bcr_manualoverrideby | Manual Override By | Lookup (System User) | No | None |
| bcr_commercialreadyat | Commercial Ready At | DateTime | No | None |
| bcr_commercialcompleteat | Commercial Complete At | DateTime | No | None |

### Relationships
- 1:N to `bcr_readinesstask` via `bcr_budgetline`
- 1:N to `bcr_purchaseorder` via `bcr_budgetline`
- 1:N to `bcr_eventlog` via `bcr_budgetline`
- 1:N to `bcr_activation` via `bcr_budgetline`

### Index recommendations
- **Alternate key**: `bcr_budgetlinekey`
- Secondary index: (`bcr_pillar`, `bcr_derivedstage`)
- Secondary index: (`bcr_owner`, `modifiedon`)

### Auditing recommendations
- Enable field auditing on stage and manual override fields.
- Audit estimated value, owner, pillar, cost center, renewal date.

### Security role permissions
- SME: Read (org), append to tasks/events.
- Pillar Lead: Read (org).
- Procurement: Read/Write (org).
- Admin: Full.
- Viewer: Read only.

| bcr_submissionnotes | Submission Notes | Multiline Text | No | None |
| bcr_submittedat | Submitted At | DateTime | No | None |
| bcr_validatedat | Validated At | DateTime | No | None |
| bcr_chasecount | Chase Count | Whole Number | Yes | 0 |
| bcr_lastchasedat | Last Chased At | DateTime | No | None |
| bcr_rejectionreason | Rejection Reason | Multiline Text | No | None |
| bcr_readinesssummary | Readiness Summary | Multiline Text | Yes for submit | None |

- N:1 to `bcr_budgetline`
- 1:N to `bcr_approvalhistory` via `bcr_readinesstask`

### Index recommendations
- Composite index: (`bcr_budgetline`, `bcr_taskcategory`, `bcr_status`)
- Index: (`bcr_assignedto`, `bcr_status`, `bcr_duedate`)

### Auditing recommendations
- Audit status transitions, checklist changes, submission fields, rejection reason.

### Security role permissions
- SME: read/write assigned rows.
- Pillar Lead: read + write validation fields.
- Procurement/Admin: read/write all.
- Viewer: read only.

## Conditional validation rules (Business Rules / plugins-free)
1. If `bcr_manualstageoverride` contains data, require `bcr_manualoverridejustification`.
2. On ReadinessTask submit intent, require checklist minimum and readiness summary.
3. Prevent closing task unless status in Approved/Rejected and required timestamps are populated.
